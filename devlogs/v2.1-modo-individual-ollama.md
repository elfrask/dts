# DTS v2.1 — Modo diálogo por diálogo para Ollama

**Fecha**: 22/07/2026

## Motivación

Ollama permite correr modelos locales sin límites de consulta, pero los modelos pequeños (3B, 8B, incluso 1.5B) fallan estrepitosamente con el modo batch tradicional. El problema: el batch envía ~200 diálogos en un solo JSON y pide al modelo que devuelva otro JSON con todas las traducciones. Los modelos pequeños no pueden mantener coherencia en estructuras tan complejas y devuelven JSONs rotos, claves faltantes, o alucinaciones.

Solución: traducir un diálogo a la vez, en texto plano, sin JSON involucrado.

## Implementación

### `formats.py`
- `ProjectConfig.single_translate: bool = False` — flag persistente en la config del proyecto

### `defaults.py`
- `DEFAULT_OLLAMA_SINGLE_PROMPT` — prompt detallado para un solo diálogo. Mismas instrucciones que el batch (comandos `\\XX`, `$~X`, `^X`, sufijos `/%`, formato `[N:TEXTO]`, restricción de longitud) pero:
  - Sin instrucciones de formato JSON
  - Sin pedido de coherencia entre diálogos
  - Termina con "Devuelve SOLO el texto traducido, sin explicaciones, prefijos ni formato adicional."

### `provider.py`
- `translate_single(key, text, prompt, config) -> str` en el ABC (levanta `NotImplementedError`)
- `OllamaProvider.translate_single()` — llama a `client.chat()` con el prompt individual + el texto. Sin `response_format="json"`, sin `think=False` (innecesario con modelos chicos). Devuelve texto plano directo.

### `translator.py`
- `use_translate()` bifurca según `single_translate + Ollama`
- `_translate_single_mode()`: itera uno por uno:
  - 3 reintentos por diálogo (1s de sleep)
  - Persiste a `lang_es_out.json` inmediatamente después de cada diálogo
  - Barra de progreso se actualiza en cada diálogo
  - Cancelación funcional
  - Si un proveedor no soporta `translate_single`, cae automáticamente a batch con los restantes
- `_translate_batch_mode()`: el batch clásico extraído a función separada, sin cambios
- **Safety net**: si `single_translate=True` pero el proveedor no es Ollama, loguea warning y fuerza batch

### `translate_tab.py` (GUI)
- Checkbox "Traducir diálogo por diálogo (para modelos Ollama pequeños)" — solo visible con Ollama seleccionado
- Al cambiar a otro proveedor, se oculta el checkbox y se fuerza `single_translate=False`
- Cuando single está activo, el Spinbox de chunk size se deshabilita (no aplica)
- Log inicial ahora muestra el modo: "diálogo por diálogo" o "por lotes (batch)"
- Tab Prompt ahora tiene un sub-notebook con dos pestañas fijas: "Por lotes (batch)" y "Individual (Ollama)" — ambos prompts visibles siempre

### `settings.py`
- `load_settings()` ya no pre-inicializa `prompt` con `DEFAULT_PROMPT`. El prompt queda vacío por defecto y cada modo usa su default al mostrar/traducir.

## Arquitectura del flujo single

```
use_translate()
  ├─ single_translate=True + Ollama
  │     → _translate_single_mode()
  │         for key, text in untranslated:
  │           for attempt in 3:
  │             OllamaProvider.translate_single(key, text, "", config)
  │               → client.chat(model, messages=[{user, prompt + "\n\nDialogo:\n" + text}])
  │               → devuelve str (texto plano)
  │             output_data[key] = str
  │             write_json()
  │
  └─ else → _translate_batch_mode()  ← intacto
```

## Lecciones aprendidas

1. **El prompt no debe ser corto** con modelos pequeños — alucinan más si no se les dice exactamente qué conservar. El prompt individual tiene el mismo nivel de detalle que el batch, solo que sin JSON.
2. **`config.prompt` no debe filtrarse al modo single**. El usuario podía tener guardado el prompt batch (con instrucciones JSON) en su proyecto, y el modelo pequeño lo seguía al pie de la letra devolviendo JSON envuelto en ```json. Se corrigió pasando `prompt=""` en single mode para que caiga al default individual.
3. **No hay sleeps entre requests** con Ollama porque es local — a diferencia del batch que tiene 7s entre chunks para respetar rate limits de APIs cloud.
