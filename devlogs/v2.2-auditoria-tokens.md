# DTS v2.2 — Auditoría de tokens y costos

**Fecha**: 23/07/2026

## Qué se agregó

Una pestaña **Auditoría** en cada proyecto que registra cada solicitud enviada a
un proveedor, con su consumo real de tokens y un costo estimado. Los datos se
persisten en `<proyecto>/audit.json`.

## Columnas de la tabla

| Columna | Descripción |
|---|---|
| Hora | Timestamp ISO de la solicitud |
| Proveedor | `commandcode`, `gemini`, `ollama`, etc. |
| Modelo | Id exacto usado |
| Tokens entrada | `prompt_tokens` / `input_tokens` / `prompt_token_count` |
| Tokens salida | `completion_tokens` / `output_tokens` / `eval_count` |
| Total tokens | entrada + salida |
| Diálogos | Cuántos diálogos iban en esa solicitud |
| Intentos | Intentos del proveedor hasta tener éxito |
| Costo est. | USD estimado según tabla de precios |

Sobre la tabla se muestran los **totales acumulados**: solicitudes, tokens de
entrada, salida, total y costo estimado.

## Extracción de uso por proveedor

`TranslationResult` ahora transporta `input_tokens`, `output_tokens` y
`attempts`. Cada provider los extrae de su propia respuesta:

- **OpenAI-compatible / CommandCode**: `usage.prompt_tokens` y
  `usage.completion_tokens` (con fallback a `input_tokens`/`output_tokens`).
- **Anthropic / CommandCode-Claude**: `response.usage.input_tokens/output_tokens`.
- **Gemini**: `usage_metadata.prompt_token_count` y
  `candidates_token_count`.
- **Ollama**: `prompt_eval_count` y `eval_count`.

El modo diálogo-por-diálogo (Ollama) no reporta tokens; sus filas se registran
igual con 0 tokens para conservar el conteo de diálogos e intentos.

## Persistencia

`audit.json` tiene esta forma:

```json
{
    "entries": [
        {
            "timestamp": "2026-07-23T14:02:11",
            "provider": "commandcode",
            "model": "deepseek/deepseek-v4.1-flash",
            "input_tokens": 18234,
            "output_tokens": 4210,
            "dialogs": 200,
            "attempts": 1,
            "cost": 0.005261
        }
    ]
}
```

El **traductor** es el único escritor: carga el archivo al iniciar, agrega la
entrada después de cada chunk exitoso y lo reescribe. Funciona igual desde la GUI
y desde el CLI (`dts run`).

## Costos estimados

`MODEL_PRICING` en `src/config/defaults.py` contiene USD por 1M de tokens
(entrada, salida) para los modelos de CommandCode (tarifas GOAT/Provider) y para
los modelos directos más comunes. Los modelos desconocidos se registran con
costo 0. `estimate_cost()` hace el cálculo.

> Son estimaciones: no incluyen cache reads/writes ni promociones temporales.

## Modo rápido (sin pausa)

El comportamiento histórico espera 7 s entre chunks para respetar rate limits.
La pestaña **Traducir** incluye el checkbox **"Desactivar pausa entre lotes (modo
rápido)"**, persistido como `paused_mode` en `settings.json`. Con `false` se
elimina la espera y se itera mucho más rápido (útil con CommandCode u Ollama).

## Prompt sin modo pensamiento

Se hizo explícita la instrucción en ambos prompts por defecto:

> IMPORTANTE: NO uses el modo de pensamiento, razonamiento extendido ni análisis
> interno. Responde directamente…

Además Gemini ya envía `ThinkingConfig(include_thoughts=False)` y Ollama usa
`think=False` en modo batch.
